# Шаблоны сущностей и листы персонажей

*English version — [templates.en.md](templates.en.md).*

Шаблон описывает, **какие поля** появляются у сущности и **как они разложены**
на листе. Один шаблон даёт три представления сразу: компактный лист в шторке
графа, полный лист в модалке и версию для печати — раскладка одна, отличается
только плотность.

Шаблон — это **заготовка, а не схема**. Хранилище сущностей остаётся свободным
мешком полей: после применения шаблона поля можно править, добавлять и удалять,
сущность от этого не «сломается». Лист никогда не прячет данные — поле, которое
не упомянуто в раскладке ни одним блоком, ни одной формулой и ни одним
`max_field`, попадает в секцию «Прочие поля» в конце листа.

Где это в интерфейсе: **Настройки проекта → Шаблоны** (конструктор) и селектор
«Шаблон» на странице сущности / в шторке графа.

---

## Из чего состоит шаблон

```
Шаблон
├── Поля (field_defs)     — что за данные и как они хранятся
└── Раскладка (layout)    — как они выглядят
    └── Регион            — band | columns | tabs
        ├── Блоки         — только у band
        └── Контейнеры    — колонка (columns) или вкладка (tabs)
            └── Секция    — карточка с заголовком, N колонок
                └── Блок  — один виджет
```

### Поля

| Свойство        | Смысл                                                        |
| --------------- | ------------------------------------------------------------ |
| `key`           | Идентификатор. На него ссылаются блоки и формулы             |
| `field_type`    | `text`, `rich_text`, `number`, `boolean`, `tag`, `attachment` |
| `label`         | Человеческая подпись (`key` — запасной вариант)              |
| `default_value` | Значение при создании сущности по шаблону                    |
| `show_on_card`  | Показывать ли поле на карточке сущности в списке             |

У уже сохранённого поля ключ заблокирован (у только что добавленного его ещё
можно поменять) — это снимает необходимость в каскадном переименовании ссылок
в раскладке и формулах. Удаление поля, на которое кто-то ссылается, конструктор
подтверждает отдельно и вычищает ссылающиеся блоки.

### Регионы

| Вид       | Что это                                                     | Где полезно                   |
| --------- | ----------------------------------------------------------- | ----------------------------- |
| `band`    | Плоская полоса блоков без карточек                          | Шапка, строка ключевых чисел  |
| `columns` | Контейнеры бок о бок, все видны одновременно                | Характеристики и навыки       |
| `tabs`    | Контейнеры переключаются табами, виден один                 | Биография, снаряжение, заметки |

Число колонок на экране решает ширина, а не настройка: в узкой шторке и на
печати `columns` схлопывается в одну колонку, а `tabs` разворачивается во все
вкладки подряд (на бумаге и в шторке переключать нечем).

Первый регион шаблона, если он `band`, рендерится как **шапка листа**: портрет,
имя, тип и полоса «пилюль» с ключевыми числами.

### Виджеты

Тип виджета намеренно отвязан от типа поля: одно и то же числовое поле может
быть обычным вводом, коробкой характеристики или рядом точек.

| Виджет          | Типы полей            | Настройки (`config`)              |
| --------------- | --------------------- | --------------------------------- |
| `plain`         | text, number, boolean | —                                 |
| `rich_text`     | rich_text             | —                                 |
| `tag_chips`     | tag                   | —                                 |
| `image`         | attachment, text(URL) | —                                 |
| `stat_modifier` | number                | —                                 |
| `dots`          | number                | `max` — сколько точек (по умолч. 5) |
| `tracker`       | number                | `max_field` — ключ поля с максимумом |
| `computed`      | —                     | `toggleable` — см. ниже           |
| `heading`       | —                     | —                                 |
| `divider`       | —                     | —                                 |

`heading` и `divider` — декоративные, поля им не нужны. `computed` тоже не
привязан к одному полю: его значение целиком задаётся формулой.

Пустая подпись блока (`label: ""`) — это осознанное «здесь подписи нет», а не
«подставь название поля». Так сделана коробка характеристики внутри секции,
которая и так называется «Сила», — иначе выходило «Сила / Сила».

## Формулы

Виджет `computed` показывает значение, вычисленное из других полей: модификатор
характеристики, бонус навыка с учётом владения, класс доспеха, лимит переносимого
веса. Само значение не редактируется — это производная величина.

Формулы намеренно **не** являются кодом на Python или JS: это маленький язык
выражений со своим парсером, без `eval` и без доступа к чему-либо, кроме полей
текущей сущности.

### Что можно писать

**Ссылка на поле** — просто его ключ: `str`, `proficiency`, `prof_stealth`.

**Числа**: `10`, `2.5`.

**Операторы** (в порядке приоритета, от сильного к слабому):

| Группа              | Операторы                | Пример              |
| ------------------- | ------------------------ | ------------------- |
| Скобки, вызов       | `( )`, `floor(x)`        | `floor((str-10)/2)` |
| Унарные             | `-x`, `!x`               | `-penalty`          |
| Умножение           | `*`, `/`, `%`            | `level * 2`         |
| Сложение            | `+`, `-`                 | `dex + 10`          |
| Сравнение           | `<`, `<=`, `>`, `>=`     | `level >= 5`        |
| Равенство           | `==`, `!=`               | `size == 1`         |
| И                   | `&&`                     | `a && b`            |
| ИЛИ                 | `\|\|`                   | `a \|\| b`          |
| Условие (тернарник) | `условие ? если_да : если_нет` | `prof ? bonus : 0` |

**Функции** — ровно шесть: `floor`, `ceil`, `round`, `abs`, `min`, `max`.
`min` и `max` принимают сколько угодно аргументов, остальные — один.

### Правила вычисления

- **Отсутствующее или незаполненное поле = 0** (в логике — «ложь»). Лист
  недозаполненной сущности показывает число, а не ошибку.
- **Логическое поле** в арифметике равно `1`/`0`; любое число, кроме нуля, в
  логике считается истиной.
- **Деление на ноль даёт 0**, а не бесконечность и не ошибку.
- Результат-число выводится со знаком (`+3`, `-1`), логический результат — как
  `✓` / `—`.
- Формула может ссылаться только на **настоящие поля**, не на другие
  `computed`-блоки. Это ограничение осознанное: циклические зависимости
  становятся невозможны в принципе, граф пересчёта не нужен.

Формула проверяется дважды: конструктор подсвечивает ошибку синтаксиса и
неизвестные ключи сразу, а бэкенд отклоняет сохранение шаблона (422), если
формула не разбирается или ссылается на поле, которого нет в `field_defs`.

### Переключатели владения

Формула описывает арифметику, а `config.toggleable` — какие её **логические**
входы показать чекбоксом прямо в строке навыка:

```
формула:   floor((dex - 10) / 2) + (prof_stealth ? proficiency : 0)
toggleable: ["prof_stealth"]
```

Получается строка «☐ Скрытность +1» — снял/поставил галочку, бонус пересчитался
на месте. Чекбоксы редактируются в режиме заполнения листа; в режиме просмотра
и на печати они видны, но заблокированы.

### Примеры

```python
# Модификатор характеристики (D&D 5e)
floor((str - 10) / 2)

# Навык или спасбросок с учётом владения
floor((dex - 10) / 2) + (prof_stealth ? proficiency : 0)

# Пассивная внимательность
10 + floor((wis - 10) / 2) + (prof_perception ? proficiency : 0)

# Класс доспеха без доспеха (монах/варвар)
10 + floor((dex - 10) / 2) + floor((wis - 10) / 2)

# Ловкость к КД, ограниченная средним доспехом
armor_base + min(2, floor((dex - 10) / 2))

# Лимит переносимого веса
str * 15

# Экспертиза: двойное владение
floor((cha - 10) / 2) + (prof_persuasion ? proficiency : 0) + (expertise_persuasion ? proficiency : 0)
```

## Пресеты

Пресет — готовый кусок листа: пачка полей плюс одна секция с блоками. Его
перетаскивают из палитры конструктора в нужную колонку или вкладку, и он
вставляется целиком вместе со своими полями. Если поле с таким ключом в шаблоне
уже есть, подставляется существующее — дубликат не создаётся.

Встроенные пресеты:

- **Характеристика + навыки (D&D)** — коробка характеристики, проверка,
  спасбросок и навыки формулами; эталонный пример того, как всё это собрано.
- **Ресурс (текущее / макс)** — трекер с полем максимума.
- **Список с чекбоксами** — набор логических полей.

Свою секцию можно сохранить как пресет проекта кнопкой в заголовке секции.
Встроенные пресеты только для чтения (правка → 409), пользовательские живут в
рамках проекта.

## Печать

Кнопка «Печать» на листе печатает **только лист** — интерфейс приложения на
печати скрывается целиком. Лист верстается в белую тему, разбивается на столько
страниц, сколько нужно, вкладки печатаются все подряд, а секции и колонки
стараются не разрываться между страницами.

## Где это в коде

| Что                              | Где                                                          |
| -------------------------------- | ------------------------------------------------------------ |
| Схемы шаблона и валидация ссылок  | `backend/src/loregraph/schemas/entity_template.py`            |
| Грамматика формул (разбор)        | `backend/src/loregraph/schemas/formula.py`                    |
| Вычисление формул                 | `frontend/src/components/sheet/widgets/formula.ts`            |
| Встроенные шаблоны и пресеты      | `backend/src/loregraph/templates/`                            |
| Рендер листа (4 режима)           | `frontend/src/components/sheet/SheetRenderer.tsx`             |
| Конструктор                       | `frontend/src/components/sheet/designer/`                     |

Грамматика реализована дважды — разбор на бэкенде (валидация при сохранении
шаблона, значений полей там ещё нет) и разбор с вычислением на фронтенде (там
есть значения сущности). Две реализации держатся в согласии общей таблицей
примеров в `backend/tests/test_formula.py`: любое изменение грамматики нужно
вносить в оба файла.
