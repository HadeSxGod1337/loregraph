# Интеграции

Loregraph не пытается заменить ваш стол — он обменивается контентом с тем, чем
вы уже пользуетесь. Раздел **Интеграции** в левом меню проекта.

Каждое подключение предлагает только то, что его инструмент действительно
умеет: у Obsidian есть экспорт, у Long Story Short его нет, и кнопки, которая
всё равно ответит ошибкой, вы не увидите.

| Инструмент             | Экспорт | Импорт | Миграция с AI | Живое чтение | Тулы для ассистента |
| ---------------------- | :-----: | :----: | :-----------: | :----------: | :-----------------: |
| **Obsidian**           |    ✅    |   ✅    |       ✅       |              |                     |
| **Foundry VTT**        |    ✅    |   ✅    |       ✅       |      ✅       |                     |
| **Long Story Short**   |         |   ✅    |               |      ⚠️       |                     |
| **Любой MCP-сервер**   |         |        |               |              |          ✅          |

---

## Два переключателя у подключения

**«Разрешить ассистенту читать этот источник»** — во время работы ассистент
может заглянуть туда за актуальными фактами (состояние мира Foundry, листы
партии) и учесть их как контекст. Обратно ничего не пишется.

**«Экспортировать автоматически после одобрения»** — каждое одобренное вами
предложение заодно уходит в этот инструмент. Экспортировать вручную можно и без
этого.

Переключатель показывается только там, где он что-то делает.

---

## Obsidian

Экспорт сущностей в хранилище на этом же компьютере: `.md`-файлы с
frontmatter и связями в виде `[[wikilinks]]` — то есть в Obsidian у вас сразу
рабочий граф.

**Настройки подключения:**

| Поле                 | Значение                                                   |
| -------------------- | ------------------------------------------------------------ |
| Путь к хранилищу     | Папка вашего vault'а                                        |
| Подпапка             | Куда писать внутри vault'а (по умолчанию `Loregraph`)       |
| Экспорт вложений     | Копировать ли картинки и файлы                              |

**Порядок работы:**

1. Нажмите **Проверить подключение** — путь существует и доступен для записи?
2. **Экспорт** сначала показывает предпросмотр: что создастся, что обновится,
   что пропустится, и как именно будет выглядеть файл.
3. Подтвердите — файлы запишутся.

Повторный экспорт **обновляет** ранее созданные файлы, а не плодит копии:
Loregraph помнит, какая сущность какому файлу соответствует.

**Импорт** возвращает заметки обратно в проект. Таблицы, чек-листы и
`==подсветка==` переживают путь туда и обратно. Цвет текста, шрифт и
выравнивание — оформление, они при экспорте в Markdown теряются; сам текст —
никогда.

Если нужно затащить в граф **чужой** vault, который Loregraph не создавал, —
это не «Импорт», а [миграция с помощью AI](knowledge.md#миграция-чужого-мира).

## Foundry VTT

Связь идёт через локальный MCP-мост к запущенному миру Foundry (например,
`foundry-vtt-mcp`): журналы, актёры, сцены.

**Настройки подключения:**

| Поле                    | Значение                                                              |
| ----------------------- | ----------------------------------------------------------------------- |
| Путь к MCP-серверу      | Файл вида `.../foundry-vtt-mcp/packages/mcp-server/dist/index.js`      |
| Путь к Node.js          | `node`, если он в PATH                                                 |
| Хост и порт Foundry     | По умолчанию `localhost:31415`                                          |
| Таймаут запроса         | По умолчанию 15 секунд                                                  |

Что доступно:

- **Экспорт** сущностей как журналов и актёров.
- **Импорт** обратно.
- **Живое чтение**: с включённым переключателем ассистент может ответить на
  «сколько сейчас HP у партии» или «что записано в журнале про порт» — данные
  берутся из работающего мира, а не из вашего лора.
- **Миграция с AI**: затащить существующий мир Foundry в граф целиком.

Foundry должен быть **запущен**, а мост — установлен и настроен. Если
инструмент недоступен, проверка подключения скажет об этом, а мир Loregraph при
этом никак не пострадает.

## Long Story Short (листы персонажей)

Импорт листов, которые игроки выгрузили с longstoryshort.app. Настраивать
нечего.

**Самый короткий путь:** страница **Сущности** → **Импорт листов персонажей**.
Кнопка сама создаст нужное подключение — заводить его заранее в настройках не
нужно. Перетащите разом все `.json`, которые прислала партия.

Что вы получите:

- Отчёт с именем **каждого** вошедшего персонажа.
- Готовый **лист**: к персонажу автоматически привязывается шаблон
  party-member — ваш собственный, если он есть в проекте, иначе встроенный.
- Повторный импорт того же файла **обновляет** персонажа, а не дублирует, и
  сохраняет поля, которые вы добавили сами.
- Файл, который не удалось разобрать, стоит одного персонажа, а не всего
  импорта.

⚠️ **Про живое чтение.** Long Story Short не отдаёт данные по ссылке — живой
запрос не работает ни у кого. Если переключатель включён, источник честно
подставляет лист **в том виде, в каком вы его импортировали в последний раз**,
и помечает данные как таковые, чтобы устаревшие HP не читались как текущие.
Хотите свежие цифры — переимпортируйте файлы.

## Любой MCP-сервер

Это универсальный путь: подключите MCP-сервер, которому доверяете, и ассистент
получит его инструменты **как есть** — так же, как когда вы подключаете MCP к
AI-агенту для кода. Никакого отдельного кода в Loregraph под каждый сервер не
требуется.

**Настройки подключения:**

| Поле                     | Значение                                                          |
| ------------------------ | ------------------------------------------------------------------- |
| Команда                  | Что запускать: `node`, `npx`, `python`…                            |
| Аргументы                | Аргументы команды                                                   |
| Переменные окружения     | Если серверу нужны ключи                                            |
| Таймаут запроса          | По умолчанию 15 секунд                                              |
| Разрешённые инструменты  | Пусто — доступны все. Список — только перечисленные                 |

Список разрешённых инструментов полезен, когда сервер умеет что-то, чего вы не
хотите отдавать ассистенту (например, двигать токены во время игры), — ограничение
задаётся настройкой, без правок кода.

**Важно:** вызовы таких инструментов приземляются **во внешнем инструменте**, а
не в мире Loregraph, и человеческого ревью у них нет по построению. Ревью
защищает канон вашей кампании; за то, что делает подключённый вами сервер,
отвечаете вы — ровно как при подключении MCP-сервера к любому другому агенту.

## Loregraph как MCP-сервер

Обратное направление: управлять Loregraph из Claude Desktop или другого
MCP-клиента. В комплекте идёт stdio-сервер `loregraph-mcp`.

Что он умеет:

- **Читать**: список проектов и сущностей, детали сущности, поиск, подграф
  связей, список связей.
- **Писать**: создать и изменить сущность, создать, изменить и удалить связь —
  через тот же слой, что и веб-интерфейс, со всеми проверками.

Чего он **не** делает:

- **Не удаляет сущности и проекты.** Удаление уносит текст, которого больше
  нигде нет; оно остаётся в веб-интерфейсе, где видно, что именно исчезнет.
- Удаление **связи** разрешено: она ничего не уничтожает и создаётся обратно.

> ⚠️ **Не включайте авто-подтверждение для инструментов записи** в своём
> MCP-клиенте. Гарантия «человек видит изменение до применения» на этом пути —
> это гарантия вашего клиента, а не Loregraph. Полноценное ревью с очередью
> черновиков живёт в веб-интерфейсе.

## Что делать, если подключение не работает

1. **Проверить подключение** — кнопка у каждого соединения, отвечает быстро и
   называет причину.
2. Путь к хранилищу или к файлу моста — абсолютный и существует?
3. Для Foundry: мир запущен, мост установлен, порт совпадает?
4. Для MCP: команда запускается вручную из терминала?
5. Секреты в настройках показываются замаскированными (`••••` и четыре
   последних символа). Если оставить маску как есть, сохранённое значение не
   изменится — это не ошибка ввода.

Удаление подключения в Loregraph **не трогает** внешние данные: файлы vault'а,
мир Foundry и листы остаются на месте.
