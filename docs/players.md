# Доступ игрокам

Loregraph умеет показывать игрокам ту часть мира, которую вы решили раскрыть.
Всё остальное остаётся скрытым — по умолчанию игрок не видит ничего, пока вы
явно не откроете карточку.

## Как это работает

**Раскрытие карточки.** У каждой сущности есть панель «Доступ игрокам» (в полном
редакторе и в боковой панели графа). Там вы:

- включаете «Раскрыта игрокам» — карточка становится видна всей партии;
- пишете **отдельный текст для игроков** (то, что им положено знать, — не ваши
  мастерские заметки);
- отмечаете, какие обычные поля игроки могут видеть; всё неотмеченное скрыто.

На доске есть кнопка-глаз для раскрытия/скрытия в один клик — это самая частая
операция за столом. Раскрытые сущности помечены точкой на узле.

**Приглашение игроков.** В `Настройки проекта → Игроки`:

- «Пригласить игрока» — вводите имя, получаете ссылку-приглашение. **Ссылка
  показывается один раз.** Потеряли — не восстанавливайте, а перевыпустите.
- «Новая ссылка» (rotate) — выдаёт новую ссылку, старая перестаёт работать.
- «Отозвать» — отключает ссылку, но **сохраняет заметки** игрока.
- «Удалить» — необратимо, вместе с заметками игрока (просит ввести имя для
  подтверждения).

**Что видит игрок.** Открыв ссылку, игрок попадает на облегчённый экран без
мастерских инструментов: список раскрытых карточек, доску только из раскрытых
сущностей (и связей между ними) и карточку с вашим текстом. Игрок ведёт свои
заметки — публичные (видит вся партия) или личные (только он). Вы, мастер,
видите все заметки, включая личные.

Обновление у игрока — раз в ~15 секунд: раскрыли NPC прямо на сессии — карточка
появится у игрока через несколько секунд.

## Как игроки подключаются

Приложение работает целиком на одном порту **8000** — и интерфейс, и API. Значит
в брандмауэре и на роутере нужен ровно один порт.

Есть три режима, каждый включается флагом при запуске. Текущий всегда видно в
`Настройки проекта → Игроки` — там же написан адрес, который получат игроки.

### 1. Только этот компьютер (по умолчанию)

```bash
start.bat
```

Никто извне не подключится. Ссылки-приглашения будут на `localhost` — годятся
проверить самому.

### 2. Локальная сеть — игроки за одним столом

```bash
start.bat --lan
```

Приложение открывается для вашей Wi-Fi/сети, ссылки получают ваш локальный адрес
(`192.168.…`). Если сетевых адресов несколько, укажите нужный:
`start.bat --lan -LanHost 192.168.1.5` (в bash: `--lan --lan-host 192.168.1.5`).
Если не открывается — разрешите порт 8000 в брандмауэре.

### 3. Интернет — игроки где угодно

```bash
start.bat --internet
```

Кроме открытия для сети, приложение просит роутер по **UPnP** пробросить порт и
берёт у него ваш публичный адрес — ссылки сразу становятся рабочими снаружи.
Правило проброса берётся с часовой арендой, продлевается пока приложение
работает, и **снимается при выходе**, чтобы закрытое приложение не оставляло
дырку в роутере.

**Сработает не у всех, и приложение честно скажет почему:**

| Что видите | Что это значит | Что делать |
|---|---|---|
| «Доступно из интернета» | Всё получилось | Раздавайте ссылки |
| Общий адрес (CGNAT) | Провайдер не выдал вам личный публичный адрес — пробрасывать некуда | Закажите «белый IP» (обычно недорогая услуга) или Tailscale |
| Роутер не ответил | UPnP выключен в настройках роутера | Включите UPnP либо пробросьте порт 8000 вручную |
| Роутер отказался | UPnP есть, но проброс не дали | Пробросьте порт 8000 вручную |

Во всех случаях **локальная сеть продолжает работать**, и ссылки автоматически
остаются на локальном адресе.

### Запасной путь: Tailscale

Работает всегда, включая CGNAT, и шифрует трафик. Цена — игрокам нужно поставить
клиент, так что это не «просто открыл ссылку»:

1. Вы и игроки ставите [Tailscale](https://tailscale.com/) и входите в одну сеть.
2. Смотрите свой адрес вида `100.x.y.z` в приложении Tailscale.
3. `start.bat --lan -LanHost 100.x.y.z`

## Шифрование (необязательно)

По умолчанию всё идёт по HTTP без шифрования. Для своего компьютера и домашней
сети это нормально; **для интернета — нет**: токен едет внутри ссылки, и тот, кто
окажется на пути, может её прочитать.

Включается так же, как в Foundry — двумя путями в `backend/.env`:

```
CAMPAIGN_SSL_CERTFILE=C:/certs/loregraph.crt
CAMPAIGN_SSL_KEYFILE=C:/certs/loregraph.key
```

После этого приложение отдаёт `https://`, и ссылки-приглашения тоже. Сертификат
на настоящий домен (Let's Encrypt) браузер примет молча; самоподписанный тоже
работает, но каждому игроку один раз придётся согласиться с предупреждением.
Указать только один из двух путей нельзя — приложение откажется стартовать, чтобы
вы не считали соединение защищённым, когда оно не защищено.

## Чего это НЕ защищает — честно

Это инструмент для игры за одним столом, а не публичный хостинг. Осознавайте
границы:

- **Ссылка = единственный секрет.** Кто угодно с ссылкой войдёт как этот игрок.
  Ссылка оседает в истории браузера, в чатах, на скриншотах. Единственная защита
  — отозвать или перевыпустить. Сам токен подобрать нельзя (256 бит), а попытки
  входа ограничены по частоте — но это не помогает, если ссылку переслали.
- **Без сертификата трафик не шифруется.** По домашней сети терпимо, наружу —
  нет. См. «Шифрование» выше.
- **В режиме `--internet` порт вашего компьютера открыт в интернет.** Мастерский
  API отвечает снаружи отказом, наружу доступна только страница входа по ссылке,
  но сам факт открытого порта — это открытый порт.
- **Доверие к loopback = доверие всему, что запущено на вашей машине.** Мастером
  считается тот, кто обращается с самого компьютера, где крутится приложение. За
  обратным прокси это доверие ломается — там ставьте `CAMPAIGN_TRUST_LOOPBACK=false`
  и настоящую аутентификацию.
- **Туннели (ngrok, Cloudflare Tunnel) — не используйте.** Через них запросы
  приходят как локальные, и любой открывший ссылку станет мастером. Проброс порта
  этой проблемы не имеет: там виден настоящий адрес игрока.
- **Ограничение частоты — не защита от распределённой атаки.** Оно в памяти
  процесса и считает по адресу.
- **Сосед на изображении.** Если вы вставили в текст для игроков картинку,
  загруженную под *другую* сущность, у игрока она не откроется — доступ к файлам
  проверяется по сущности.

Отзывайте ссылки, когда сессия закончилась.
