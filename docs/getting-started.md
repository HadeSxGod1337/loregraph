# Установка и первый запуск

Loregraph — локальное приложение: сервер и браузерный интерфейс работают на
вашем компьютере. Ставить ничего вручную не нужно, скрипт запуска делает всё
сам.

---

## Быстрый старт

1. Скачайте репозиторий (кнопка **Code → Download ZIP** на GitHub или
   `git clone`) и распакуйте.
2. Запустите:
   - **Windows** — двойной клик по `start.bat` в корне папки;
   - **macOS / Linux** — `./start.sh` (или `bash start.sh`) в терминале из
     корня папки.
3. Дождитесь, пока откроется браузер.

Скрипт сам:

- доставит недостающие инструменты (`uv` для Python, Node.js);
- подтянет свежие изменения из git, если папка склонирована;
- установит зависимости;
- при первом запуске предложит выбрать LLM-провайдера и источник эмбеддингов;
- поднимет оба сервера и откроет приложение.

**Чтобы остановить**: закройте окно консоли (Windows) или нажмите Ctrl+C
(macOS/Linux).

Пока приложение работает, скрипт периодически проверяет, не появилось ли
обновление, и сообщает, что перезапуск его подтянет.

---

## Первый запуск: два вопроса

### Провайдер LLM

Ассистент работает на **вашем** ключе. Варианты:

| Выбор                                 | Что нужно                        | Стоимость                          |
| ------------------------------------- | -------------------------------- | ---------------------------------- |
| **Anthropic** (по умолчанию)          | Ключ `sk-ant-...`                | Платите Anthropic за токены        |
| **OpenAI**                            | Ключ OpenAI                      | Платите OpenAI                     |
| **Ollama** (локально)                 | Установленный Ollama с моделью   | Бесплатно, качество ниже облачных  |
| **Пропустить** (Enter)                | Ничего                           | Приложение работает без ассистента |

Поддерживаются и другие провайдеры (Google, Mistral, DeepSeek, Groq, xAI,
OpenRouter, Cohere, Together, Fireworks, Cerebras, Perplexity, Nebius) — их
настраивают через файл конфигурации, см. ниже.

**Пропустить — нормальный выбор.** Весь ручной редактор работает без ключа; на
вкладке ассистента будет инструкция, как подключить его позже.

### Источник эмбеддингов

Эмбеддинги — то, что даёт смысловой поиск по лору («найди что-нибудь про
портовые интриги»).

- **Локально** (по умолчанию) — многоязычная модель скачивается один раз при
  первом использовании и работает у вас на машине. Бесплатно, лор никуда не
  уходит.
- **Через API** (OpenAI и другие) — качество выше, но текст сущностей уходит
  провайдеру и тарифицируется.
- **Отключено** — смыслового поиска нет; ручной редактор при этом работает
  полностью.

## Что появится после запуска

Если база пуста, создаётся **демо-проект** — чтобы приложение не открывалось
пустым экраном. Его можно спокойно удалить.

Левое меню проекта:

| Раздел           | Что там                                                          |
| ---------------- | ----------------------------------------------------------------- |
| **Сущности**     | Список всего в мире, поиск, фильтр по типу, импорт листов партии   |
| **Граф**         | Визуальная карта мира и связей, шторка ассистента                 |
| **AI-ассистент** | Диалог и ревью черновиков на отдельной странице                   |
| **Интеграции**   | Подключения к Obsidian, Foundry, Long Story Short, MCP-серверам   |
| **Настройки**    | Инструкции для ассистента, шаблоны, база знаний, переиндексация    |
| **Справка**      | Краткая встроенная справка                                        |

Тема оформления, акцентный цвет и язык интерфейса (русский / английский) — в
нижней части боковой панели.

## Где лежат данные

Всё в папке `data/` внутри проекта:

| Путь                        | Что это                                                |
| --------------------------- | -------------------------------------------------------- |
| `campaign.sqlite3`          | **Главный файл**: миры, сущности, связи, шаблоны, настройки |
| `attachments/`              | Загруженные картинки и файлы                            |
| `knowledge/`                | Исходники документов базы знаний                        |
| `chroma/`                   | Поисковый индекс — пересобираемый, бэкапить не обязательно |
| `agent_checkpoints.sqlite3` | Незавершённые диалоги ассистента, ждущие ревью          |
| `import_checkpoints.sqlite3`| Незавершённые массовые импорты                          |

**Резервная копия**: скопируйте `campaign.sqlite3`, `attachments/` и
`knowledge/` — этого достаточно, чтобы восстановить всё содержимое. Индекс
пересобирается кнопкой переиндексации в настройках проекта.

Есть и второй способ: **экспорт проекта** в один JSON-файл (кнопка на карточке
проекта в списке) — удобно для переноса на другой компьютер. При импорте все
внутренние ссылки, `[[wikilinks]]` и вложения корректно переносятся.

## Подключить ассистента позже

Создайте файл `backend/.env` (рядом с `backend/pyproject.toml`):

```env
CAMPAIGN_ANTHROPIC_API_KEY=sk-ant-...
```

Для другого провайдера:

```env
CAMPAIGN_LLM_PROVIDER=openai
CAMPAIGN_OPENAI_API_KEY=sk-...
```

Полностью локально, без ключа:

```env
CAMPAIGN_LLM_PROVIDER=ollama
CAMPAIGN_OLLAMA_BASE_URL=http://localhost:11434
CAMPAIGN_LLM_MODEL_ASSISTANT=<имя вашей модели>
CAMPAIGN_LLM_MODEL_EXTRACTION=<имя вашей модели>
CAMPAIGN_LLM_MODEL_GENERATION=<имя вашей модели>
```

После правки `.env` **перезапустите бэкенд** — настройки читаются при старте.

Ключ маскируется во всех логах и сообщениях об ошибках; файл `.env` не
попадает в git.

Полный список настроек — в
[`backend/src/loregraph/config.py`](../backend/src/loregraph/config.py).
Самое полезное:

| Переменная                        | По умолчанию | Зачем менять                                             |
| --------------------------------- | ------------ | -------------------------------------------------------- |
| `CAMPAIGN_AGENT_RUN_TOKEN_BUDGET` | `200000`     | Жёсткий потолок расхода на один прогон                   |
| `CAMPAIGN_LLM_MODEL_GENERATION`   | Sonnet-класс | Качество/цена творческой генерации                       |
| `CAMPAIGN_LLM_MODEL_ASSISTANT`    | Haiku-класс  | Цена самого частого — обычного диалога                   |
| `CAMPAIGN_EMBEDDING_PROVIDER`     | `local`      | `disabled` — совсем без индексации                       |
| `CAMPAIGN_DATA_DIR`               | `./data`     | Хранить кампании в другом месте                          |

## Обновление

Если папка склонирована через git, скрипт запуска **спрашивает** перед
обновлением. Когда выходит новая версия, он показывает, что за версия и что в
ней меняется, и предлагает: обновить сейчас, позже или пропустить эту версию.
Выбор запоминается — режим (спрашивать / обновлять сразу / не проверять) хранится
в `backend/data/update.conf`, там же его можно поменять, как и в приложении
(боковая панель → «Оформление» → «Обновления»).

Двойной клик по `start.bat` остаётся без присмотра: если на вопрос никто не
ответил за 30 секунд, скрипт просто продолжает запуск без обновления. Если у вас
есть локальные изменения в папке проекта, автоматическое обновление
пропускается — сохраните или отмените их и запустите снова.

Если папка скачана архивом (без git) — проверка обновлений недоступна: скачайте
новую версию и **перенесите папку `data/`** в неё.

Перед обновлением загляните в [CHANGELOG.md](../CHANGELOG.md): записи,
затрагивающие сохранённые кампании, несут раздел **Migration** с описанием,
нужны ли ручные действия. Схема базы обновляется автоматически при старте.

## Запуск для разработчиков

```bash
# бэкенд
cd backend
uv sync
uv run uvicorn loregraph.main:app --reload      # http://localhost:8000

# фронтенд
cd frontend
npm install
npm run dev                                      # http://localhost:5173
```

Есть `Makefile`: `make install`, `make dev-backend`, `make dev-frontend`,
`make check` (линт + типы + тесты).

Документация API работающего сервера — `http://localhost:8000/docs`.
